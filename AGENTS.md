# Multisim circuit work

- Identify the deliverable, required part models, inputs, outputs, and verification method. Follow the user's circuit structure and textbook method. Use the simplest implementation with the specified stock Multisim parts. Prefer the Native master database or a verified stock part from an existing project. Run requested simulation on the actual deliverable and report any missing part or model that blocks verification.
- Use Native for schematic edits, layout inspection, interactive simulation, and supported numerical analyses. Reuse upstream edit batches and checks. Hand off to COM only for a required COM capability, cross-check, or explicit request.
- Verify electrical connectivity with native pins, nets, or netlist evidence. Inspect the native drawing separately for collisions, detours, and legibility.
- Place parts to shorten their busiest connections before routing. Keep power and ground leads short. End each branch at a native junction placed where the visible lines actually split. In `native_edit_batch`, use `route_wire` with the current connector coordinates, then `repair_wire_geometry` if endpoints are misaligned. Inspect the exported drawing for shared wire segments that split away from the junction dot. If an exported switch appears displaced, compare it with the live schematic before changing its wiring.
- Set placement from the actual pin connections. Group parts by signal path and place each group near the pins it serves. Align successive stages and reserve room for shared trunks with short branches before routing. When a route detours or crowds a label, consider moving its parts first. Read the new pin positions before rerouting. Compare selected routes with `native_simplify_wiring` and use `native_check_layout` to locate remaining collisions.
- When rearranging a connected block, use `native_compare_placements` to generate layouts for repeated branches or compare explicit candidates. Review module metrics and unroutable wires. Use the same image region before and after when demonstrating a layout change.
- For a whole sheet, use `native_plan_sheet_layout` to compare placement and routing with inferred or specified functional blocks. Lock parts the user wants in place. Apply a candidate on the working copy if its placement and routing improve the drawing. Inspect the native comparison at the same scale.
- For a small crowded block, use `native_plan_local_placement` with explicitly movable components and junctions. Compare with fixed placement before applying a larger change.
- Use `native_preview_ordered_wiring` for matched pins that share a routing corridor. Apply reviewed plans with `native_apply_layout_plan` on the same working copy and request matched image regions when showing the result.
- Use a working copy when testing changes to a supplied circuit. Confirm the active document before saving or handing it off, and preserve the original unless the user requests in-place changes.
- During layout iterations, inspect the drawing and check the affected pins against their original nets. Reuse the previous simulation result when the verified circuit's component parameters and pin-to-net assignments match. For a new circuit, an electrical change, or an explicit request for retesting, run the relevant simulation from the final saved file and report the result.
- Tie requested screenshots, waveforms, and test tables to the saved deliverable. Report the observed result and any unverified behavior. Use input combinations that cover relevant enable or inhibit states. In F5 mode, test the actual switches and indicators when interaction matters.
- Keep fixtures, local configurations, and NI assets out of Git. Run the public unit suite with `python -m unittest discover -s tests -v`. Describe real Multisim checks separately from unit tests.
